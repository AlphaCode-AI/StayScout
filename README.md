# StayScout

말한 조건 그대로, 갈 수 있는 숙소만 골라 주는 에이전트예요. 카테고리는 **캠핑장**과 **펜션·민박** 두 가지이고, 호텔·모텔도 같은 구조로 붙일 수 있어요.

채팅으로 조건을 말하면 Gemini가 어떤 도구를 쓸지 스스로 정하고, 공공데이터와 지도 API(카카오·구글·네이버)로 조건을 확인한 뒤 근거와 함께 순위를 보여 줘요. 확인하지 못한 조건은 지어내지 않고 "확인 필요"로 남겨요.

## 실행

```bash
pnpm install
cp .env.example .env   # 키 입력
pnpm sync:all          # 처음 한 번, 캠핑장 데이터 받기 (data/ 에 저장)
pnpm sync:pension      # 처음 한 번, 펜션·민박 데이터 받기
pnpm dev               # http://localhost:3000
```

### .env

| 키 | 용도 |
|---|---|
| `GOCAMPING_SERVICE_KEY` | 공공데이터포털 인증키(디코딩). 관광공사·행안부·산림청 데이터에 같이 써요 |
| `GEMINI_API_KEY` | Gemini 에이전트. 없거나 한도에 걸리면 규칙 기반 처리로 자동 전환 |
| `GEMINI_MODEL` | 비워 두면 쓸 수 있는 Flash 모델을 자동 선택 |
| `KAKAO_REST_API_KEY` | 주소→좌표, 지금 이름·전화번호 대조 |
| `GOOGLE_PLACES_API_KEY` | (선택) 펜션 홈페이지·구글 평점. 하루 `GOOGLE_DAILY_LIMIT`회(기본 30) |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | (선택) 네이버 클라우드 API HUB 지역 검색. 구글에 링크가 없을 때 홈페이지·블로그·인스타그램 찾기. 하루 `NAVER_DAILY_LIMIT`회(기본 50) |

`.env`는 git에 올라가지 않아요(`.gitignore`).

## 데이터

### 캠핑장

`pnpm sync:all`이 아래 순서로 받아서 `data/camps.json` 하나로 합쳐요. 결과: 등록 캠핑장 약 4,639곳.

| 스크립트 | 출처 | 하는 일 |
|---|---|---|
| `sync-gocamping.mjs` | 한국관광공사 고캠핑 | 기본 목록, 시설, 사이트 유형·크기, 소개글 |
| `sync-extra.mjs` | 고캠핑 | 추가 필드(대여 장비, 체험 프로그램, 등록·수정일 등) |
| `sync-registry.mjs` | 전국 야영장 등록 현황 (odcloud 15037499) | 고캠핑을 보강하고, 없는 곳은 `reg-` 번호로 추가 |
| `sync-pettour.mjs` | 관광공사 반려동물 동반여행 | 반려견 동반 조건 → `data/pet.json` |
| `sync-public.mjs` | 행안부 일반야영장업 인허가, 산림청 자연휴양림 | `data/license.json`, `data/forest.json` (느린 API라 쪽마다 `data/.cache/`에 저장하고 이어 받음) |
| `merge-public.mjs` | 위 두 파일 | 영업 상태·인허가일·최초 인허가일과 휴양림 정보를 붙임. 휴·폐업만 있는 곳은 검색에서 빠짐 |

`pnpm test:gocamping 포천`으로 API 연결을 확인할 수 있어요.

### 펜션·민박

`pnpm sync:pension`이 `scripts/sync-pension.mjs`를 단계별로 실행해 `data/pensions.json`을 만들어요. 결과: 39,634곳(펜션 11,150 · 민박 28,484). 주소로도 좌표를 못 찾은 5곳만 빠져요.

| 단계 | 출처 | 하는 일 |
|---|---|---|
| `rural` | 행안부 농어촌민박업 인허가 (56,084건) | 영업 중인 민박 목록, 객실 수, 좌표 |
| `tourist` | 행안부 관광펜션업 인허가 (1,699건) | 관광펜션 지정 여부 |
| `lodging` | 행안부 숙박업 인허가 (59,074건) | 객실이 많아 숙박업으로 신고한 단지형 펜션·풀빌라 (약 2,200곳 추가). 호텔·콘도 업태와 모텔·호텔 이름은 빼고, 이름에 펜션·풀빌라·독채 등이 있거나 "스테이·빌라·하우스"면서 읍·면에 있는 곳만. (공공데이터포털 "행정안전부_문화_숙박업 조회서비스" 활용 신청 필요) |
| `geocode` | 카카오 주소 검색 | 인허가에 좌표가 없는 곳(약 3,300곳)의 주소를 좌표로 바꿔 `data/.cache/pension/geo.json`에 저장 |
| `tour` | 관광공사 숙박 정보 (펜션) | 객실별 기준·최대 인원, 가격(비수기·성수기 × 주중·주말), 취사·바비큐·부대시설, 사진 |
| `merge` | 위 셋 | 이름·주소·좌표로 합침. 인허가 좌표(EPSG:5174)를 위경도로 변환 (경기도 공식 좌표와 비교해 오차 중앙값 약 10m) |

API가 느리고 끊겨서 쪽마다 `data/.cache/pension/`에 저장하고, 한 번에 정해진 시간만 받은 뒤 다시 실행하면 이어 받아요. 서버는 `camps.json`·`pensions.json`이 바뀌면 다시 읽어요.

가격은 체크인 날짜로 고르고(성수기 7/15~8/25, 주말 = 금·토 숙박), 조건 `price:<상한>[:<시즌>]`으로 비교해요.

### 검색할 때 추가로 쓰는 것
- **카카오 로컬**: 상위 후보의 지금 이름·전화번호를 대조해서 이름이 바뀐 곳을 알려 줘요 (1일 캐시).
- **링크 점검**: 예약·홈페이지 링크가 실제로 열리는지 확인해요. 주소 자체가 없는 경우만 "안 열림"으로 표시해요.
- **캠핑톡 공공 캠핑장**: 날짜·구역별 남은 자리 (아래 참고).
- **구글 Places · 네이버 지역 검색** (펜션): 상위 10곳의 홈페이지·블로그·인스타그램 링크와 구글 평점. 같은 시·군·구에 있고 이름이 비슷할 때만 같은 곳으로 봐요 (24시간 캐시, 하루 호출 한도).

검색 결과는 먼저 보내고(`/api/search`), 링크·평점·링크 열림 확인은 화면이 따로 `/api/enrich`로 받아 채워요. 표에는 그동안 "링크·평점 찾는 중…"이 보여요.

## 구조

```
lib/
  agent-loop.ts   Gemini 에이전트 루프. 도구 11개(조건 정리·초기화, 탐색, 조건 완화, 상세, 조건 확인, 비슷한 곳, 빈자리, 문의 메시지, 되묻기, 답변)를
                  Gemini가 골라 호출. 숙소는 번호·이름·"방금 본 곳"으로 지정
  agent.ts        도구 구현, 순위, 결과 문구. Gemini 실패 시 정해진 순서로 처리하는 기본 파이프라인
  llm.ts          조건 해석 프롬프트와 조건 목록
  parse.ts        규칙 기반 조건 해석 (Gemini 실패 시)
  interpret.ts    두 해석기를 같은 형태의 조건으로 맞춤
  data.ts         데이터 로드(캠핑장+펜션·민박), 시즌·주말 가격, 조건별 판정(✓ 확인 · ≈ 추정 · ✕ 아님 · ? 확인 필요)과 근거, 이동 시간 추정
  availability.ts 캠핑톡 빈자리 조회
  kakao.ts        카카오맵 이름 변경 대조
  google.ts       구글 Places로 펜션 홈페이지·평점 찾기
  naver.ts        네이버 지역 검색으로 펜션 링크 찾기
  names.ts        숙소 이름 비교, 외부 API 하루 한도(한국 날짜 기준)·하루 캐시
  links.ts        링크 열림 확인, 전화번호 형식 확인
  profile.ts      내 정보(인원·반려견·카테고리별 늘 원하는 조건)를 검색 조건에 반영
  examples.ts     첫 화면 예시 문장 (캠핑장·펜션 따로)
  types.ts        공용 타입
app/
  page.tsx           채팅 화면, 카테고리 선택, 대화 기록(URL별·카테고리 뱃지), 헤더
  result-panel.tsx   오른쪽 결과 패널(추천 후보, 상세 탭, 순위 변화)
  components.tsx     결과 표, 판정 배지, 상세 화면·사진
  profile-modal.tsx  내 정보 설정 (캠핑장 / 펜션·민박 탭)
  home-modal.tsx     우리 집(동 단위) 설정
  history.ts         대화 기록·내 정보 브라우저 저장
  api/search         검색 API (결과를 먼저 보냄)
  api/enrich         상위 10곳 링크·평점 채우기 (숙소 id만 받음)
  api/geocode        주소 검색 API
```

## 개인정보

- 우리 집 주소는 이동 시간 추정에만 써서 **동까지만** 저장하고, 좌표도 약 1km 단위로 뭉개요.
- 내 정보와 대화 기록은 모두 브라우저(localStorage)에만 저장하고 서버에는 저장하지 않아요.

## 빈자리 확인

- 캠핑톡 공공 캠핑장 달력(로그인 없이 공개)에서 날짜·구역별 남은 자리를 조회해요. 현재 평택 소풍정원 등 일부만 가능해요.
- 공식 API가 아니라 바뀌거나 막힐 수 있어요. 사용자가 요청할 때만 조회하고 5분 캐시해요. 정식 서비스는 제휴가 필요해요.
- 다른 예약처(캠핏, 네이버 예약 등)는 확인했다고 말하지 않고 예약처 바로가기만 보여 줘요. 봇 차단은 우회하지 않아요.

## 한계와 다음 단계

- 이동 시간은 직선거리 기반 추정 → 길찾기 API로 교체 예정
- 빈자리 자동 확인은 일부 캠핑장만
- 공공데이터가 오래된 곳이 많아 최신성 표시로 보완
- 펜션 홈페이지·평점은 상위 10곳만, 하루 호출 한도 안에서만 찾아요
- 펜션 반려견·오션뷰 같은 조건은 소개글 추정이 많아요
- 호텔·모텔: 펜션·민박처럼 데이터 스크립트와 조건 목록을 추가하면 같은 판정·순위 구조를 재사용

## 회사 네트워크(Zscaler)에서 실행할 때

Zscaler가 HTTPS 연결 중간에서 인증서를 바꿔 끼워서, Node가 캠핑톡 같은 사이트에 연결하지 못해요(`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`).
`pnpm dev` / `pnpm start`는 `certs/zscaler-root.pem`(Zscaler 루트 인증서, 공개 인증서)을 `NODE_EXTRA_CA_CERTS`로 같이 믿도록 설정돼 있어요. 회사 밖이나 다른 컴퓨터에서도 문제없이 동작해요.
